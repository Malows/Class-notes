# OpenCode Agent Guide for ClassNotes

## Commands

- pnpm only (`.npmrc` sets `engine-strict`; never npm/yarn).
- `pnpm dev` – Vite dev server. `pnpm build` runs `validate:i18n` **before** `vite build`.
- `pnpm check` – `tsc --noEmit` then `svelte-check` (a tsc failure hides svelte-check results). Needs `.svelte-kit`, generated by `svelte-kit sync` via `prepare` on install.
- `pnpm lint` (oxlint) / `pnpm format` (oxfmt).
- Tests (Vitest + jsdom): `pnpm test` is **watch mode** — use `pnpm test:client` / `pnpm test:server` for one-shot, or `pnpm exec vitest run <path>` for a single file. Colocated as `*.test.ts`; runes need the `.svelte` infix (`*.svelte.test.ts`).
- `openspec validate --all` must pass; completed changes live under `openspec/changes/archive/`.

## Architecture (Svelte 5, runes forced)

- Flow: page/component → client store → client service (`apiFetch`) → thin `src/routes/api/v1/*/+server.ts` → server service → repository. Business rules in services, SQL in repositories.
- `src/lib/client/` browser-only (`components/`, `stores/`, `composables/`, `services/`, `utils/`); `src/lib/common/` env-agnostic (`types/`, Zod `schemas/`, `i18n/`, `constants/`); `src/lib/server/` Node-only (`database/`, `repositories/`, `services/`). Never import `$lib/server/*` from client code.
- Stores are runes classes in `.svelte.ts`, provided via Svelte context (`initStoreContext()` in `+layout.svelte`) and read with `getContext(StoreKey.*)`. Pages **and** the sidebar must use those context instances; the module-level singletons are never populated.
- Responses are `{ data }`, errors `{ error }` with a status; `apiFetch` unwraps `data` and throws `Error(result.error)`. Conflicts are 409 (duplicate legajo, cross-cursada pair), unknown targets 404.
- Entity pages follow `PageWithAdd` + `ModalManager` (`composables/useModal.svelte.ts`) + an entity modal + `ConfirmDialog`.
- URLs carry **no numeric ids**: `/faculties/{faculty}/subjects/{subject}/periods/{year}/{semester}/commissions/{commission}`. Slugs for faculty/subject/commission, year+semester for periods; the API stays id-based and pages resolve slugs in memory (`bySlug`, `findInScope`, periods by year+semester). Old numeric URLs no longer resolve — don't add fallbacks.

## Data model (no `students` table — don't assume it)

- `persons` (name + optional **legajo**, unique among non-deleted rows) and `enrollments` = a person **taking a subject in a period** (`subject_period_id`) with an **optional** `commission_id`.
- One active enrollment per `(person, subject_period)`. `commission_id IS NULL` means "enrolled, awaiting a commission": that is the pending list, a valid state, not an error.
- Registration is search-then-create: legajo first, else exact name inside the cursada, ASCII-case-insensitive (SQLite `NOCASE` semantics — accented variants need the legajo). A pasted batch reuses instead of failing; the registry modal rejects a taken legajo with 409.
- `assignments` hang off `subject_period_id` (a TP belongs to a cursada, not to a period); `deliveries` reference `enrollment_id`. Creating an assignment pre-creates one delivery per enrollment of its cursada.
- `attendances` are keyed by `(assignment_id, enrollment_id)` with `status` `PRESENT`|`ABSENT`, `recorded_on` and `commission_id` (derived server-side). **No row means "not taken"** — attendance rows are never pre-created, unlike deliveries. That tri-state is the point; don't fan out placeholders.
- Attendance has three routes: commission grid, cursada grid, and take mode (`.../commissions/{slug}/attendance/take?assignment_id=`). Guests from another commission are deliberately **out of scope**: no `is_guest`, no picker. `commission_id` and the composite FKs stay for later.
- Composite FKs force every attendance into the cursada of its assignment *and* its enrollment; the parents carry `UNIQUE (id, subject_period_id)` for that.
- `periods` is global (`year`,`semester`) and many subjects share it. Anything scoped to "a subject in a period" must filter by `subject_period_id` — never by period alone, or grids and lists leak across subjects.

## Database (SQLite + Drizzle)

- Schema in `database/schema.ts` + `relations.ts`; one folder per migration (`<timestamp>_<name>/migration.sql`); `applyDrizzleMigrations` also reads legacy flat `*.sql`.
- **Migrations are tracked** in `schema_migrations` (`src/lib/server/database/migrate.ts`): each deploy applies only pending versions, so schema changes no longer require deleting `class-notes.db*`. A legacy database (tracked table absent, `faculties` present) is baselined instead of re-run. `MIGRATIONS_DIR` overrides where the SQL is read from (the image copies it to `/app/migrations`).
- `DATABASE_PATH` is read at **runtime** (`$env/dynamic/private`); the old `DATABASE_NAME` was build-inlined and is gone. Production refuses to start without it, and the server refuses to boot against an unmigrated file.
- Demo fixtures (`seed.ts`) are a development convenience: a new file hydrates automatically in `vite dev`; a production build only seeds with `SEED_DEMO_DATA="true"` or `pnpm db:seed`. `NODE_ENV=development` in a production image does not seed.
- `pnpm build` also compiles `build/migrate.js` and copies `build/migrations`; the container entrypoint runs it before starting the server.
- `pnpm db:generate` output must be hand-checked: SQLite table rebuilds can emit `ALTER ... ADD NOT NULL` without a default (invalid), and drizzle-kit asks for `--hints` when it cannot tell a rename from a create. Rename the generated folder to `<timestamp>_<feature>`.
- Everything is soft-deleted: queries filter `deletedAt IS NULL`, deletes set it. Partial unique indexes free values on delete — **except** `periods(year, semester)`, which is not partial, so a soft-deleted period blocks recreating that pair.
- Repository tests run against a real in-memory SQLite built from the migrations and seed, so they are integration tests.
- Drizzle 1.0 codecs: raw `sql` expressions bypass column codecs, so better-sqlite3 hands back `bigint` for integer results (`COUNT(*)`, scalar subqueries, `pending_count`). Every raw numeric aggregate must end in `.mapWith(Number)` (or use drizzle's `count()` helper) before it reaches a `number` field, otherwise the API throws on `JSON.stringify`.

## Testing quirks

- The attribute is `data-test-id`, not `data-testid`: call `configure({ testIdAttribute: "data-test-id" })` before `screen.getByTestId`, or query the DOM directly.
- Mounting anything with `DialogBase` in jsdom needs stubs for `HTMLDialogElement.prototype.showModal`/`close` and `Element.prototype.animate` (Svelte `fade`).
- `ResponsiveTable` renders the desktop table **and** the mobile cards at once, so text appears twice in the DOM — use `getAllBy*` or scope to a `data-test-id`.
- Page render tests mock `$app/state` (params + url), `$app/navigation` (`goto`) and `$lib/client/services/api`, then `mount` with a `Map<StoreKey, Store>` context.

## i18n

- One JSON per namespace in `src/lib/common/i18n/{en,es}/`, and each namespace must be registered in `i18n/config.ts` — a new file without a loader silently resolves to the raw key. `pnpm validate:i18n` checks EN↔ES parity and that every `$t('...')` literal exists.

## Academic hierarchy

- `faculties` → `subjects` → (`subject_periods` ↔ `periods`) → `commissions`; enrollments sit on `subject_periods`.
- Slugs: faculties globally unique, subjects per faculty, commissions per subject+period, using partial unique indexes (`WHERE deletedAt IS NULL`) and regenerated on rename (own row excluded, numeric suffix on collision) — **renaming changes the URL**.
- Payloads carry slug helpers (`Subject.faculty_slug`, `Period.subject_slug`, pending summary with slugs and year/semester).
- Changing the hierarchy means updating shared types + Zod schemas + stores + client/server services + repositories + migrations together.

## Workflow

- Env from `.env` (see `.env.example`); Sentry/Plausible are optional and no-op when unset — never add required env vars.
- Significant changes go through OpenSpec: proposals and deltas under `openspec/changes/**`, synced into `openspec/specs/**` when archived. `opsx-*` commands and skills live in `.opencode/`.
- No CI (`.github/workflows/` is empty): run `pnpm check`, `pnpm lint`, `pnpm validate:i18n` and the relevant suites before committing.
